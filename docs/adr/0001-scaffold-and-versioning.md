# ADR 0001: Scaffold and versioning

- Status: accepted
- Date: 2026-09-12

## Context

Empty repo, zero tools. We want a shared baseline that scales without becoming a junk drawer.

## Decision

- Flat layout `tools/<name>/` + `metadata.yaml` as a machine-checkable contract.
- Categories as metadata, not folders.
- `TOOLS.md` generated by `scripts/list-tools.sh`; `docs/index.md` hand-curated.
- Repo-level SemVer (`vX.Y.Z` + GitHub Releases) + per-tool `version` in `metadata.yaml`. Keep-a-Changelog `CHANGELOG.md`.
- CI must pass with 0 tools. `tools/.gitkeep` keeps the folder tracked.
- English everywhere.

## Consequences

- Adding a tool = scaffold + README + example + test + metadata. More upfront friction, less bitrot.
- Recategorizing is cheap (change one field). Moving folders is expensive (avoided).
- `AGENTS.md` + `new-tool`/`verify-tool` skills pin how humans and AIs work here.
