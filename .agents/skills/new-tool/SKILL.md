# New Tool

Create a new tool from scratch, following the full baseline order. Working language: English.

## When to use

Use ONLY when the user asks to create, add, or scaffold a NEW tool in `tools/`.
If the code already exists somewhere else, use `restructure-tool` instead.
To check quality afterwards, use `verify-tool`.

## Full order

### 1. Validate the name

- `kebab-case`, 2–48 chars, `^[a-z0-9]+(-[a-z0-9]+)*$`. Verb first when possible (`check-latency`, `rename-photos`).
- Reject reserved names: `common`, `template`, `test`, `scripts`, `tools`, `templates`.
- Reject duplicates: search `tools/` and `docs/index.md` first.

### 2. Scaffold (never hand-copy)

```bash
bash scripts/new-tool.sh --lang bash|python|powershell|ruby <kebab-name>
```

This creates `tools/<name>/{README.md, metadata.yaml, main.<ext>, tests/test_basic.<ext>}` and, unless
you pass `--no-examples`, `examples/basic.<ext>`, with `__TOOL_NAME__` already replaced and every
non-chosen language removed (`ext` = `sh`|`py`|`ps1`|`rb`).

### 3. Fill metadata.yaml

```yaml
name: <kebab-name>        # must equal the folder name
description: What it does in max 12 words
category: automation|text-data|network-system|dev
owner: "@user"
status: incubating        # every new tool starts here
compat: all                # all, or the real OS targets (macOS, Linux | Windows 10+)
impact: read-only          # read-only | local | system
last_verified: YYYY-MM-DD  # set today, keep current
```

### 4. Complete README.md

Fixed headings, fill body only, max 300 words excluding code:

1. One-line purpose (what it does + for whom).
2. Use for (2–3 yes-cases) / Not for (1–2 no-cases + alternative).
3. Requirements: runtime, environment variables, network.
4. Impact: `read-only` | `local` | `system`, plus writes, privileges and rollback.
5. Quickstart: ONE copy-paste block that runs in <5 min with expected output.
6. Options list (max 6 bullets, real flags only).
7. Limits & status: known failures + what it was NOT tested with.
8. License & credits (`Apache-2.0` by default, owner, contact).

- Directories, environment variables and network hosts it touches, plus the impact level.

### 5. Implement the entrypoint

- Keep ONE executable: `main.sh`, `main.py`, `main.ps1`, or `main.rb` (`chmod +x`). Delete the rest.
- Contract: `--help` exits 0 and prints `Usage:`, `--version` prints the version, no-arg run exits non-zero WITHOUT destroying anything.
- Logs to stderr, data to stdout. Exit codes: `0` ok, `2` usage error, `1` failure.
- Portable shell: `#!/usr/bin/env bash` + `set -euo pipefail`, bash 3.2 compatible (no assoc arrays, no `mapfile`, no `&>>`), portable `sed -i.bak`, no `realpath`, no `date --iso-8601`.

### 6. Test (and optional example)

- `tests/test_basic.<ext>`: native to the entrypoint, already scaffolded (executable check, `--help`,
  no-arg safety, idempotency). Keep it green; extend only with deterministic fixtures (<100KB, no
  network, no `sudo`, <30s). One test, not two — see `docs/adr/0002-per-language-tests.md`.
- `examples/basic.<ext>` is OPTIONAL. Add one copy-pasteable happy path with a real fixture when it
  earns its place; skip it (`--no-examples`) when the README Quickstart already covers the flow.

### 7. Verify (same gate as CI)

```bash
bash tools/<name>/tests/test_basic.sh          # bash tool
python3 tools/<name>/tests/test_basic.py       # python tool
ruby tools/<name>/tests/test_basic.rb          # ruby tool
pwsh -File tools/<name>/tests/test_basic.ps1   # powershell tool
bash scripts/list-tools.sh --check
git ls-files '*.sh' | xargs -r shellcheck -S warning      # bash only
git ls-files '*.py' | xargs -r -n1 python3 -m py_compile  # python only
git ls-files '*.rb' | xargs -r -n1 ruby -c                # ruby only
```
Run the ONE test that matches the entrypoint; run `examples/basic.<ext>` with the same runner if it
exists. CI runs each tool's native test on every OS with that runtime.

All must be green. Then add a `CHANGELOG.md` entry under `[Unreleased]` and open ONE single-purpose PR.

## Forbidden

- Creating `tools/category/tool` (categories are metadata, not folders).
- Editing `TOOLS.md` by hand (regenerated by `list-tools.sh`).
- Secrets, `curl | bash`, default `sudo`, `chmod 777`, `/Users/...` paths, binaries without source.
- Cross-dependencies between `tools/*`.
- Inventing results: run the commands and report real exit codes.
